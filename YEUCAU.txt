Bạn là senior full-stack developer.

Hãy xây dựng hoàn chỉnh một MVP Patient Portal bằng Next.js để bệnh nhân của Bệnh viện/Phòng khám Đa khoa An Phú có thể đăng nhập và tra cứu lịch sử khám bệnh.

MỤC TIÊU

Tạo một web application responsive ưu tiên giao diện mobile, chạy được trên desktop và điện thoại.

Đây là phiên bản DEMO/MVP.

TUYỆT ĐỐI:
- Không kết nối Oracle thật ở giai đoạn này.
- Không sử dụng dữ liệu bệnh nhân thật.
- Tạo mock data/dữ liệu demo.
- Thiết kế code sao cho sau này có thể thay data provider bằng REST API kết nối Oracle mà không phải viết lại giao diện.
- Không hard-code secret.
- Tất cả secret phải nằm trong environment variables.
- Không expose database credentials ra browser.

16. DATABASE DESIGN
--------------------------------------------------

  id UUID PK

  full_name varchar
  birth_date date

  created_at timestamp

  id UUID PK
  patient_id UUID FK
  his_visit_id varchar
  visit_date timestamp
  department_name varchar
  doctor_name varchar
  status varchar
  notes text

diagnoses
  id UUID PK
  visit_id UUID FK
  icd10_code varchar
  diagnosis_name varchar
  diagnosis_type varchar

--------------------------------------------------
18. FUTURE ORACLE ARCHITECTURE
--------------------------------------------------

Thêm file:

docs/ORACLE-INTEGRATION.md

Giải thích architecture tương lai:

Browser
→ HTTPS
→ Patient Portal
→ Patient API
→ Oracle HIS

Tuyệt đối không:

Browser
→ Oracle trực tiếp.

Oracle username/password không bao giờ nằm trong Next.js client.

Tương lai backend có thể dùng:

ASP.NET Core Web API
Oracle.ManagedDataAccess
Dapper

Các endpoint tương lai:

GET /api/me

GET /api/me/visits

GET /api/me/visits/{id}

GET /api/me/lab-results

GET /api/me/imaging-results

GET /api/me/prescriptions

GET /api/me/insurance

GET /api/me/appointments

Không thiết kế endpoint:

/patients/{mabn}

cho bệnh nhân tự truyền MABN.

Backend phải xác định bệnh nhân từ authenticated user/token.

19. SECURITY
--------------------------------------------------

Thiết kế theo nguyên tắc:

- HTTPS only
- authentication required
- authorization theo patient
- không cho bệnh nhân thay MABN để xem người khác

- không expose service role key
- environment variables
- rate limiting design
- audit log
- session timeout
- input validation
- sanitize error messages
